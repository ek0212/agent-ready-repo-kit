# Docs And Writing Rules

- Use direct, plain English.
- State assumptions and limitations clearly.
- Avoid unsourced claims, unverified quotes, and stale metrics.
- Prefer stable constraints over temporary status.
- Use relative paths in durable repo docs.
- Remove comments or docs that restate nearby code.
- Keep useful traps, contracts, setup commands, and decision rationale.
