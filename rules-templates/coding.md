# Coding Rules

- Inspect nearby code before editing.
- Make the smallest reasonable change that satisfies the request.
- Match existing naming, error handling, formatting, test style, and abstractions.
- Add or update tests for bug fixes, critical logic, and changed public behavior.
- Keep comments for contracts, traps, constraints, and decision rationale.
- Verify with the narrowest relevant command before reporting completion.
- Ask before changing public APIs, auth, permissions, billing, data deletion, or dependencies.
